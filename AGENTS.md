# Notes pour les assistants de code

Carnet est une appli web statique (PWA), sans framework ni étape de build. Garde-la ainsi sauf demande contraire.

- Langue : toute l'interface et les messages sont en français, ton tutoiement.
- `js/app.js` : un seul script classique (pas de modules ES), pour que `index.html` marche aussi en double-cliquant dessus.
- État : objet `S` (`S.tx` = opérations, `S.profile.recurring` = fixes mensuels, `S.profile.budgets` = plafonds par catégorie, `S.profile.goals` = objectifs d'épargne `{id, label, target, saved, date?: "YYYY-MM"}`, `S.profile.cats` = catégories modifiées ou ajoutées, `S.profile.accounts` = comptes `{id, name, budget, opening, from: "YYYY-MM"}` (le compte `main` existe toujours : lis `accounts()`), `S.profile.carry` = report `{on, from}`, `S.profile.lastBackup` = date du dernier export). Toujours écrire via `api.*` puis `render()`.
- Stockage : `localStorage`, clé `carnet-argent-v1` (JSON en clair, ou boîte chiffrée `{enc:"carnet",…}` si le verrouillage est activé). N'écris jamais directement : passe par `saveLocal()`. Si le format change, migre les anciennes données dans `loadLocal()` au lieu de les perdre.
- Une opération : `{id, type: "in"|"out", cat, amount, label, date: "YYYY-MM-DD", ts, goal?, acc?}` (`goal` = versement ou retrait d'un objectif ; le total d'un objectif est `saved` plus ces opérations). Un virement : `{id, type: "tr", cat: "autre", amount, label, from, to, date, ts}` : toujours filtrer sur `type` avant d'additionner. Un fixe : `{id, type, cat, amount, label, since: "YYYY-MM", until?: "YYYY-MM", day?: 1-31, freq?: "week"|"quarter"|"year", wd?: 0-6, acc?, hist?: [{until, amount}]}`. `amount` est le dernier montant par passage, `hist` garde les anciens : lis-le pour un mois donné avec `activeFixes()` (`amount` = total du mois, `unit` = par passage, `n` = nombre de passages).
- Reste à vivre : `compute(ym).reste` = `net` (résultat du mois) + `carry` (report). Seuls les comptes dans le budget comptent.
- Catégories : `CATS` en haut de `app.js` contient celles de base. `CAT` est le résultat avec `S.profile.cats` : lis toujours `cat(k)` ou `CAT`, et appelle `refreshCats()` après un changement.
- Sécurité : pas de ressource externe, ni de script ou d'attribut `style` en ligne (CSP dans `index.html`). Les valeurs calculées passent par `data-bg`, `data-w`, etc. et `applyStyles()`. Tout texte inséré dans le HTML passe par `esc()`, toute donnée lue d'un fichier ou du stockage passe par `cleanData()`. Un nouveau champ doit y être ajouté, sinon il disparaît au chargement.
- Synchro : section « synchro » de `app.js`. `S.sync` (jeton, clé) reste dans le stockage chiffré, jamais dans `S.profile` ni dans les exports, et exige le verrouillage. `saveLocal()` date les changements (`upd`) et note les suppressions (`profile.deleted`) par comparaison, donc le code n'a rien à dater lui-même. Tout nouveau type d'élément doit être ajouté à `syncLists()` et `syncMerge()`. `connect-src` n'autorise que `api.github.com`.
- Couleurs : uniquement via les variables CSS de `:root` dans `css/style.css`, avec leurs équivalents en thème sombre.
- Tests : `node --test tests/carnet.test.js`, à lancer après chaque modification et à compléter pour toute nouvelle règle de calcul. Ils chargent `js/app.js` tel quel dans un faux navigateur, sans dépendance. Ajoute au fichier de test le nom de toute nouvelle fonction à tester (`EXPORTS`).
- Après toute modification publiée, incrémente `CACHE` dans `sw.js`, et ajoute tout nouveau fichier à `FILES`.
- Montants : formatés avec `Intl.NumberFormat("fr-FR", {currency: "EUR"})`.
